# 领域边界

跟踪中欧班列箱货编组、口岸节点、异常处置与交付承诺。

现有领域资料围绕以下边界组织：

- 订单与箱货谱系
- 装载与编组
- 口岸和换装节点
- 异常责任
- 目的站交接

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。

## 履约服务业务约束

### 1. 箱货身份

- 每个客户订单（Order）保存客户、交付承诺区间和其下全部箱货（ShipmentUnit）。
- 每只箱货保存箱号（container_no，物理身份）、箱货编号、货类、重量、
  随箱单证、所属班列（铁路区段）与装载计划时间。
- 同一箱货的拆分（split）、合并（merge）、换班（reassign）以谱系事件
  双向串联，任意时刻都能回答“这批货从哪来、现在在哪只箱里”。
- 合并后源箱退役，不再接受回执。

### 2. 节点顺序

固定节点链：已接单 → 已装箱 → 南昌发运 → 到达霍尔果斯 → 查验放行 →
换装宽轨 → 口岸出境 → 到达比什凯克 → 目的站交接完成。

- 回执只能推进到紧邻的下一节点，跳节点报 OutOfOrder。
- 同一回执编号重复到达，或同节点内容一致的回执再次到达：
  判重丢弃，绝不重复推进节点。
- 已处理回执的编号与箱号绑定，挪用到其他箱号进入核对。

### 3. 单证一致

- 每个节点保存首次回执的重量与单证（类型/编号/版本）指纹。
- 编号相同但重量变化、单证版本变化或出现未登记单证：
  抛 ReconciliationNeeded 进入人工核对，节点不推进，回执不消费；
  内容更正后用原回执编号重发即可正常推进。

### 4. 局部冻结

- 危险属性、查验异常、海关暂扣只冻结受影响的单只箱货（freeze_unit），
  带处置工单号和责任方；冻结箱任何节点不得推进。
- 整列其他箱子的查验、换装、出境、交付照常进行
  （train_status 区分 running / frozen / delivered）。
- 处置结论为放行则解冻；结论为部分暂扣可先拆分：
  受影响部分继续冻结，其余部分放行随原班列运行。
- 受影响箱改走下一班时记录换班、节点回退重走并顺延承诺，
  换班完成自动解除冻结。

### 5. 交付承诺

- 每只箱货维护预计交付区间 eta_min/eta_max；初始按装载计划估算，
  延误（record_delay）与改配（reassign_to_next_train）顺延并留痕。
- explain_order 按客户订单给出：每只箱的当前位置/节点、下一责任人、
  是否冻结及责任方/工单、预计交付区间、是否 at_risk / breached，
  以及可直接向客户解释的中文摘要（哪只箱、为什么、影响了哪项承诺）。

## 停机恢复

所有状态变更先通过领域规则校验，再以 JSON 事件追加写入事件日志
（src/store.py）：

- 校验失败的命令不落任何事件；
- 写入追加并 flush/fsync；
- 进程重启后重放全部事件重建状态，延误、改配、异常处置跨停机继续推进；
- 日志损坏或事件 schema 不识别时显式报错，不静默跳过。
