# 跨境班列箱货节点与异常责任

跟踪中欧班列箱货编组、口岸节点、异常处置与交付承诺。

## 参与方与事实

主要参与方包括班列运营方、货代、铁路承运方、口岸查验人员、目的站交接人员。领域资料记录以下已经确认的事实：

- 南昌国际陆港开行直达比什凯克的中欧班列
- 列车装载太阳能组件、陶瓷餐具和灯具
- 线路经霍尔果斯口岸出境并直达中亚商贸枢纽

## 货运履约服务

`src/` 在领域资料之上实现了可持久化的货运履约服务：

- `src/model.py`：节点（Stage）、节点责任主体、订单、班列、箱货状态
- `src/eventlog.py`：追加式 JSONL 事件日志，append + fsync，重启重放恢复状态
- `src/service.py`：履约服务，对外提供建档、回执摄取、异常处置、拆分合并、
  延误改配与订单解释

服务为每个订单保存箱号、封条、货类、重量、单证、装载计划、所属班列车皮、
节点回执和责任主体，并落实五条业务约束：

- **箱货身份**：拆分、合并以谱系串联；改走下一班记录原班列与新班列
- **节点顺序**：回执只能推进到紧邻下一节点，跳节点拒绝并留痕
- **单证一致**：同箱号重量或单证变化进入核对，不推进节点
- **局部冻结**：危险属性或查验异常只冻结涉事箱，整列其他箱子照常运行
- **交付承诺**：延误修订 ETA、改配修订承诺区间，可按订单解释当前去向、
  下一责任人与预计交付区间

回执摄取 `ingest_receipt()` 的处置结果：`advanced`（推进）、`duplicate`
（重复回执，不重复推进）、`review`（重量/单证差异待核对）、`rejected`
（冻结或跳节点）。

`contracts/context.schema.json` 描述领域资料结构，`fixtures/context.json`
提供不含真实身份信息的示例，`src/rail_context.py` 负责读取和校验这些资料。
完整业务规则见 `docs/domain-rules.md`。

## 开发命令

运行测试：

```bash
python3 -m unittest discover -s tests -v
```

编译检查：

```bash
python3 -m compileall -q src tests
```

端到端演示（南昌→霍尔果斯→比什凯克，含暂扣、局部冻结、改走下一班与交付）：

```bash
python3 -m src.demo
```

三条命令只读写仓库内文件或临时目录，不需要连接外部业务系统。
